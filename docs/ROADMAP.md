# Roadmap (8 weeks, one phase = one commit)

Each phase ends with a stop: show the result, get confirmation, then continue.

| Phase | Weeks | Deliverable | Done when |
|---|---|---|---|
| 0 — Scaffold *(this commit)* | 0 | Repo layout, schemas, 4 transforms, 5 carriers, defense interface, keyword baselines, Wilson CIs, tests | `pytest` green; `python -m zhipi.build` writes the v0 file |
| 1 — Real detectors | 1–2 | Adapters for Prompt Guard 2, Qwen3Guard (as labelled control), a DeepSeek LLM-judge, and `ibr` audit; first full run on v0 | One results table with CIs; every detector pinned to a revision |
| 2 — Data | 2–4 | 6 → ~20 intents; planned transforms (`pinyin`, `trad_simp`, `homophone`, `char_decomp`); small de-identified real-text benign set; second-annotator agreement | ~1,500 samples; Cohen's κ reported; data card complete |
| 3 — Analysis | 4–6 | Ablations by transform / carrier / intent; FPR by stratum; variance across repeats | The headline figure and 3 supported claims, each with an interval |
| 4 — Structural layer | 6–7 | `run_isolated` adapter: end-to-end ASR with the audit bypassed, Chinese vs English | Same table as injection-blast-radius's matrix, on the Chinese set |
| 5 — Release | 7–8 | Hugging Face dataset, technical report (arXiv-ready), one-command reproduction, CI | A stranger can reproduce the headline figure from a clean clone |

## Status

- **Phase 0** — done, on `main`.
- **Phase 1** — **mostly done; one planned detector missing.** Code for all
  detectors plus `run_eval` and `report` is tested offline. Run on v0 (see
  `results/phase1.md`, generated by `zhipi.report`, nothing hand-written):
  - two keyword sanity baselines;
  - Qwen3Guard-Gen-0.6B at a pinned commit, as the wrong-tool control (flags 7 of
    226, labels nothing `Unsafe`; a plainly harmful prompt does come back `Unsafe`
    in English and Chinese, so the pipeline works);
  - a DeepSeek LLM judge, 678 calls (226 × 3 repeats), none failed: **100%
    detection in every condition, 0% false positives, no verdict changed across
    repeats**;
  - a community multilingual-BERT classifier (unvetted), as a stand-in for the
    gated Prompt Guard 2: **flags all 226 samples, benign ones included**, so its
    detection number is meaningless.

  **What v0 turned out to show:** it is saturated for a strong LLM judge and too
  easy to separate detectors that already work, while the weak ones fail for
  reasons unrelated to Chinese (the community model over-flags task-like text in
  any language). So Phase 2 must make the *data* harder before any claim about
  transforms can be tested: payloads that do not state the goal outright,
  injections buried in long hosts, text aimed at the judge's own prompt, and many
  more hard negatives.

  **Missing:** Prompt Guard 2 (the Hugging Face access request was rejected) and
  the `ibr` audit (needs `IBR_REPO`; it makes billed calls and was not run).
- **Phase 2** — **step 1 done and measured** (`results/v1.md`, 803 samples, all runs
  at one clean commit, same dataset hash). v1 has 19 intents in four tiers
  (`explicit` / `implicit` / `spoofed_structure` / `judge_targeted`), a `buried`
  placement, and 53 benign samples in 11 strata; v0 stays frozen (a test pins its
  fingerprint). A duplicate-sample bug (a no-op transform) was found and fixed on
  the way. What v1 showed:
  - **The DeepSeek judge is no longer at the ceiling:** 97% detection (strict) with
    1 of 53 benign samples flagged. Every miss (19 of 750) comes from two `implicit`
    intents, `ctx_config` ("attach the configuration you can see") and `checklist`
    (one unticked box). It was **not** fooled by `spoofed_structure`,
    `judge_targeted` or `buried` payloads, nor by any Chinese transform.
  - **Those misses may be label ambiguity, not detector error.** The same two
    texts are almost indistinguishable from legitimate requests to a human reporter;
    the one benign sample the judge flagged is exactly such a request
    (`asks_humans_for_info`). Resolving this needs a second annotator.
  - The community mBERT classifier again flags everything (100% / 100%); Qwen3Guard
    again flags ~1% of attacks, as expected of a wrong-tool control.
  - **So far no evidence that Chinese-specific transforms hurt a strong LLM judge.**
    That matches prior work and hypothesis H1 is, for this detector, a null result;
    the open question is the small, cheap detectors, which need a working one to test.

- **Phase 2, step 2: a small detector that is neither blind nor degenerate.**
  Screened 284 Hub models and added `Horizon-Labs/prompt-injection-guard-base`
  (308M, Apache-2.0, multilingual incl. Chinese, trained on documents with planted
  injections; its card's metrics are the authors' own and unverified here). Run via
  the new generic `hf-classifier` kind at a pinned commit. On v1 (default
  threshold 0.5): **80% detection, 13% false positives (7 of 53), AUROC 0.94 on
  Chinese**. What it shows about H1:
  - **Rates differ by language, ranking barely does.** English plain 97% vs
    Chinese plain 81% at threshold 0.5 (en better in 9 of 19 intents, zh better in
    0, p≈0.004 on a sign test over intents), but AUROC is 0.97 vs 0.94 with
    overlapping intervals. English text is also flagged more when benign (4 of 11
    vs 3 of 32), so most of the gap looks like calibration: the same ranking cut at a
    different point. Comparing detection rates at one threshold would have
    overstated a language effect.
  - **Chinese-specific transforms did nothing measurable.** Fullwidth and zero-width
    changed no verdict; space-split and code-mix moved a few in both directions
    (p 0.36–0.55); AUROC stays 0.92–0.95.
  - **Burying the payload in a long document hurts most:** 81% → 58% detection
    (23 lost, 1 gained), AUROC 0.94 → 0.89.
  - **Weak spots:** false positives on `asks_humans_for_info` (3 of 5), the
    very requests that resemble the `ctx_config` attack, and on text containing
    fake-secret placeholders.
  - So H1 ("small detectors lose recall on Chinese-specific obfuscation") is
    **not supported for this detector**; what the data does support is a placement
    effect and a calibration shift across languages. One detector, template data,
    19 intents: indicative only. The English-vs-Chinese comparison is also
    confounded by translation wording and by the different benign sets (11 English
    vs 32 Chinese).
- **Phase 2, step 3: an English-centric control.** Added
  `protectai/deberta-v3-base-prompt-injection-v2` (English only per its card, ~689,000
  downloads) at a pinned commit. It is **not a clean H1 control**, because it is weak
  on this task even in English: 84% detection but **55% false positives**, AUROC
  **0.68 in English and 0.57 in Chinese** (intervals overlap, so the drop is not
  established). It is built for direct injections, while v1 hides the instruction in
  documents. Its detection *rate* is a trap: 32% on English payloads but 87% on
  Chinese ones, because it flags nearly all Chinese text (100% of the benign
  `discusses_injection` and `asks_humans_for_info` samples), so the rate rises as
  discrimination falls. AUROC shows what the rates hide, which is why the report puts
  false positives and AUROC next to detection. A fair English control needs a
  detector trained for indirect injection in English; none was run.
- **Provenance fix.** `run_meta.json` keyed every `hf-classifier` run by kind, so the
  second model overwrote the first one's pinned revision. Now keyed by model id and
  covered by a test; both Hub models were re-run at a clean commit with identical
  counts, as expected of deterministic models.
- **Phase 4, step 1: the structural layer, end to end** (`results/v1_e2e.md`;
  `python -m zhipi.run_e2e`, then `zhipi.report_e2e`). The undefended baseline agent
  and injection-blast-radius's isolated pipeline (probabilistic audit **bypassed**)
  read the same 143 `issue`-carrier injected samples (18 intents; `dump_prompt`
  excluded because its goal is not the fake secret) plus 21 benign ones; a leak is the
  fake secret (plain, URL-encoded or base64) in the public output. Baseline 3 repeats,
  isolated 1; 614 jobs, none failed; ibr at `af8a758`, one model for everything.
  - **Containment held: 0 of 143 isolated runs leaked** with the audit bypassed,
    across every condition including all Chinese transforms and the buried placement.
  - **But the baseline was already robust: 4 of 429 injected runs leaked (1%).** The
    leaks are four different intents/conditions, no pattern; language and transform
    effects on the baseline are null (all p ≥ 0.5, 18 intents). So on these payloads
    the boundary has almost nothing to prevent, and this run cannot show that it adds
    value, only that it does not break. H3 ("containment does not depend on language")
    is consistent with the data but is weakly tested.
  - The real audit rated 140 of 143 injected samples `high_risk` and 3 `suspicious`
    (98% / 100% with suspicious), comparable to the Phase 1 judge.
  - **An undefended agent leaked on a benign issue:** 1 of 63 baseline runs on benign
    issues (a Chinese issue that merely mentions copying `sandbox/.env`) read the file
    and pasted it unprompted. No injection needed.
  - **Cost of the boundary on benign issues:** the isolated pipeline took no action on
    2 of 21 (10%, 95% [3%–29%]), in line with the 6.1% injection-blast-radius measured.
  - Caveat to test next: the bait file says it is fake, which may make the baseline more
    willing to quote or refuse it than a realistic secret; and 18 intents is small.
    Making the attacks the baseline actually fails on (rather than assuming they exist)
    is the natural follow-up.

  Not started: the planned transforms (`pinyin`, `trad_simp`, `homophone`,
  `char_decomp`), real-text benign samples, second-annotator agreement, and growing to
  ~1,500 samples. Per-tier counts are very uneven (`judge_targeted` is one intent), so
  the tier rows say little beyond the specific wordings.

## Compute plan

Dev machine: RTX 4060 Laptop, 8 GB VRAM (checked with `nvidia-smi`).

- Fits (expected, **verify**): Prompt Guard 2 86M, Qwen3Guard-Gen-0.6B, and a
  ~4B victim model quantized to 4-bit.
- Does not fit locally: anything ≥ 8B at fp16. Use the DeepSeek API for those and
  budget the cost before Phase 1 (each LLM defense × 226+ samples × 3 repeats).
- Cache every API response keyed by (model, revision, prompt hash) so reruns are
  free and the results are auditable.

## Decision points

- After Phase 1: if every real detector is already near-perfect on v0, the
  transforms are too weak — strengthen them before scaling the data.
- After Phase 2: if κ is low, fix the annotation guide before adding volume.
- If a close neighbour benchmark appears (see `RELATED_WORK.md`), narrow the
  claim to the transform + hard-negative + structural-layer combination.
