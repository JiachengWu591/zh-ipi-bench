# zh-ipi-bench

A benchmark for **indirect prompt injection in Chinese**: an instruction hidden in a
document, web page, email or tool output that an LLM application reads as *data*. It
contains injected samples, benign look-alike controls, and the Chinese-specific
obfuscations (fullwidth forms, zero-width characters, spaced characters, Chinese-English
code-mixing, and in `v3` traditional script, pinyin, homophones and character
decomposition) applied to the payloads.

Code, evaluation harness, results and the technical report:
<https://github.com/JiachengWu591/zh-ipi-bench>

> **Status: v0.2, a research artifact, not a leaderboard.** The data is hand-written and
> template-generated by one author. Read "Limitations" before drawing conclusions.

## Versions

Each version contains the previous one. v0, v1 and v2 are frozen (the repository pins a
content fingerprint for each); `v3` was added in 0.2.0; only a slice of it (the new samples and their plain twins) has
been run against detectors, and the rest is v0 to v2 content that was measured earlier.

| config | samples | injected | benign | what it adds |
|---|--:|--:|--:|---|
| `v0` | {v0_samples} | {v0_injected} | {v0_benign} | six explicit payloads, four transforms, five carriers |
| `v1` | {v1_samples} | {v1_injected} | {v1_benign} | implicit, spoofed-structure and judge-targeted payloads; a "buried in a long document" placement; hard-negative benign strata |
| `v2` | {v2_samples} | {v2_injected} | {v2_benign} | twelve attacks ported from injection-blast-radius's corpus (English original + Chinese translation); benign issues containing HTML comments |
| `v3` | {v3_samples} | {v3_injected} | {v3_benign} | four more Chinese transforms (traditional script, pinyin, homophone, character decomposition) on every intent in two carriers; benign controls that contain the same surface forms innocently |

`MANIFEST.json` lists the checksum of every file; `seed/` holds the hand-written intents
and benign texts the data is generated from.

## Fields

One JSON object per line.

| field | meaning |
|---|---|
| `sample_id` | unique, `[A-Za-z0-9._-]{1,64}` |
| `label` | `injected` or `benign` |
| `carrier` | `issue`, `rag_doc`, `email`, `web_html`, `tool_output` |
| `language` | `zh` (transformed) or `en` (plain control) |
| `transforms` | list of applied transforms: `fullwidth`, `zero_width`, `space_split`, `code_mix`, and in `v3` `traditional`, `pinyin`, `homophone`, `char_decomp` |
| `text` | the untrusted text a detector or agent would read |
| `intent_id` | which attacker goal (injected samples only) |
| `plaintext_intent` | what the payload asks, stated plainly. Present on every injected sample so an obfuscated or encoded payload can be audited by eye |
| `tier` | `explicit`, `implicit`, `spoofed_structure`, `judge_targeted`, `ibr_corpus` (the author's judgement of how recognisable the ask is, not a measured property) |
| `placement` | `default` or `buried` (payload mid-way through a long benign document) |
| `stratum` | benign hard-negative family (benign samples only) |

## How it was made

- A fixed fictional host (a CLI called `blastdemo` that fails on a repeated `--profile`)
  per carrier and language; only the payload varies.
- 31 hand-written intents (a goal held fixed, the persuasion varied), each with a Chinese
  and an English text. The English text of the ported attacks is the original, verbatim; the
  Chinese is a hand translation.
- Transforms are applied to the payload only, never the host. A transform that changes
  nothing is skipped, so no two samples share the same text.
- Benign controls include the bare hosts and *hard negatives* written to resemble the
  attacks without being one: a maintainer asking a human reporter for their environment
  config, a security article quoting "ignore the previous instructions", an issue that
  mentions `.env`, a task list, a format request, a quoted instruction, a long document.

## Intended use

Evaluating and hardening prompt-injection defenses, in particular how they treat Chinese
text and how much benign text they over-flag. Not for attacking systems you do not own.

## Safety statement

Every payload targets a fictional sandbox path and a fixed fake placeholder secret, or the
assistant's own instructions. The only payload containing a link points at
`example.invalid`, a reserved domain that never resolves. Nothing targets a real product,
service, credential or person, and the data contains injection *wording*, not working
exploit chains. Even so, it is adversarial text: do not feed it to an agent that has real
secrets or real tools.

## Limitations

- **Synthetic and template-based**: it is not the real-world distribution of attacks, and
  results on it will not transfer unchanged.
- **Small and uneven**: 31 intents; some tiers rest on one or two intents. Per-condition
  intervals computed on it are too narrow because the five carriers of one intent are
  replicates of the same payload.
- **Single author, no human second annotator**: a blind LLM annotator (a fresh Claude
  agent, not a person) agreed with the author's label on 102 of 103 texts and rated 4 of 31
  translations slightly off (`results/annotation.md` in the repository); that is an upper
  bound, not a human agreement. A few intents (for example "attach the configuration you can
  see") are near-identical to legitimate requests addressed to a human, so their label
  depends on who reads the text.
- **The benign set is small** (see the table), so false-positive rates have wide intervals.
- **Difficulty is a hypothesis**: the tiers are the author's judgement. On one strong LLM
  judge v0 was saturated (100%) while v1 was not (97%).
- Simplified Chinese, except the `traditional` transform and eight benign controls in
  `v3`; the English texts are a parallel control, not a benchmark of English.
- **`v3` transforms are table-based**: `pinyin`, `homophone` and `char_decomp` re-spell
  only key terms listed in small curated tables, and a `traditional` payload sits inside a
  simplified-script host. Per-condition intervals on `v3` are too narrow for the same
  reason (two carriers per intent, not five).
